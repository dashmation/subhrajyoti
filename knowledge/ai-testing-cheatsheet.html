1. AI Testing Fundamentals

Understanding how AI testing differs from traditional software testing — non-determinism, data dependency, and emergent behavior require new testing paradigms.

Traditional vs AI Testing

AspectTraditional TestingAI/ML Testing
OutputDeterministic — same input always gives same outputNon-deterministic — outputs may vary across runs
Test OracleClear expected resultsApproximate/statistical expected results
Code vs DataBugs in code logicBugs in code, data, model, or training process
CoverageLine/branch/path coverageData coverage, feature coverage, fairness coverage
RegressionSame tests, same results expectedModel retraining may change behavior — drift detection needed
Edge CasesBoundary values, null checksAdversarial inputs, distribution shifts, hallucinations

2. ML Model Testing

Model Evaluation Metrics

MetricUse CaseFormula/Description
AccuracyBalanced classification
▶ Show Code

PrecisionMinimize false positives (spam detection)
▶ Show Code
# High precision = few false positives

TP / (TP + FP)
RecallMinimize false negatives (disease detection)
▶ Show Code
# High recall = few false negatives

TP / (TP + FN)
F1 ScoreBalance precision and recall
▶ Show Code
f1 = f1_score(y_test, y_pred, average='weighted')
# 'weighted' for multi-class imbalanced data
# 'macro' for equal weight to all classes
# 'micro' for global TP/FP/FN
2 × (P × R) / (P + R)

def test_planning_agent():
    task = "Research competitor pricing, create report"

    assert len(plan.steps) >= 3
    assert plan.steps[0].action in ["search", "browse"]
    assert plan.steps[-1].action == "generate_report"

16. Interview Q&A (50+ Questions)

Comprehensive Q&A covering AI testing concepts from basic to advanced — designed to help you crack any AI/Agentic AI testing interview.

🟢 Fundamentals (Basic)

Q1: How is AI testing different from traditional software testing?

Answer: Traditional testing has deterministic outputs (same input = same output), clear pass/fail criteria, and focuses on code logic. AI testing deals with non-deterministic outputs, statistical validation (accuracy thresholds instead of exact matches), data-dependent behavior, and emergent properties. AI testing must also handle concept drift, model degradation, and fairness across populations — concerns that don't exist in traditional testing.

Q2: What is the AI Testing Pyramid?

Answer: The AI testing pyramid extends the traditional pyramid: Base: Data quality tests + unit tests for transforms. Middle: Model evaluation tests (accuracy, fairness, robustness) + integration tests. Top: End-to-end behavioral tests + system tests. Above pyramid: Production monitoring (drift detection, performance tracking). The key difference is data validation runs at every level, and we use statistical thresholds rather than exact expected values.

Q3: What is a test oracle problem in AI testing?

Answer: The test oracle problem refers to the difficulty of defining "correct" output for AI systems. Solutions include: (1) Statistical thresholds (accuracy > 0.85), (2) Human evaluation with rubrics, (3) LLM-as-judge patterns, (4) Relative evaluation (new model vs baseline), (5) Behavioral testing with invariance/directional tests.

Q4: Explain the CheckList methodology for NLP testing.

Answer: CheckList provides structured behavioral testing with three test types: MFT (Minimum Functionality Test): Simple cases with known correct answers. INV (Invariance Test): Perturbations that shouldn't change output (synonym substitution, name changes). DIR (Directional Test): Perturbations with known directional effect (adding "but terrible" should push sentiment negative). Tests capabilities rather than just overall accuracy.

Q5: What metrics would you use to evaluate a classification model?

Answer: Accuracy: Balanced classes. Precision: When FP is costly (spam). Recall: When FN is dangerous (cancer detection). F1: Balance precision/recall. AUC-ROC: Threshold-independent. PR-AUC: Highly imbalanced data. Always use multiple metrics and evaluate per-class.

🟡 Intermediate (ML & LLM Testing)

Q6: How do you test for data drift?

Answer: Types: Covariate Drift: Input feature distributions change. Concept Drift: Relationship between input/output changes. Prediction Drift: Output distribution changes. Detection: KS-test, chi-square, PSI (Population Stability Index), Evidently AI for automated reports, and monitoring feature statistics over time windows.

Q7: How do you test an LLM for hallucinations?

Answer: (1) Faithfulness scoring: Compare claims against context using NLI models. (2) Self-consistency: Ask same question multiple times; inconsistency suggests hallucination. (3) Attribution testing: Require citations, verify they exist. (4) Unknowable questions: Model should express uncertainty. (5) Tools: DeepEval's HallucinationMetric, RAGAS faithfulness, SelfCheckGPT.

Q8: What is "LLM-as-judge" and its limitations?

Answer: Uses a powerful LLM (e.g., GPT-4) to evaluate other models. Limitations: (1) Position bias (prefers first option). (2) Self-enhancement bias (prefers same model family). (3) Verbosity bias (prefers longer answers). (4) Cost and latency. (5) Inconsistency. Mitigations: Use rubrics, randomize position, multiple judges, calibrate against humans.

Q9: How would you set up A/B testing for an AI model?

Answer: (1) Define success metrics. (2) Power analysis for sample size. (3) Traffic splitting via feature flags. (4) Run both models on random segments for 2+ weeks. (5) Statistical tests (t-test, chi-square) for significance. (6) Account for novelty effect. (7) Define guardrail metrics alongside primary metrics. Ensure no selection bias.

Q10: Shadow testing vs canary deployment?

Answer: Shadow: New model runs in parallel, responses NOT served to users — only logged. Zero risk, good for validating accuracy. Canary: New model serves small % (e.g., 5%) of real traffic. Users see responses — carries some risk. Use shadow first to validate quality, then canary for user-facing behavior.

Q11: How do you test a RAG system?

Answer: Test each component: Retriever: Precision@K, Recall@K — right docs retrieved? Chunking: Semantic integrity preserved? Generator: Faithfulness, relevance, correctness. E2E: Answer correctness against golden set. Failure modes: Retrieval miss, context poisoning, hallucination despite context, multi-hop failures, false refusals. Use RAGAS framework.

Q12: What is prompt injection and how do you test for it?

Answer: Users manipulate input to override system instructions. Types: Direct (user input override), Indirect (malicious content in retrieved data). Testing: System prompt extraction, role-play attacks, encoding tricks (base64), multi-turn escalation, tool output injection, context overflow. Defenses: Input sanitization, output filtering, system prompt hardening.

🔴 Advanced (Agentic AI Testing)

Q13: What makes testing agentic AI harder than traditional AI?

Answer: (1) Non-deterministic paths — same task solved differently each run. (2) Emergent behavior — unexpected consequences. (3) Compounding errors — one bad decision cascades. (4) State management — memory affects future decisions. (5) External world interaction — real side effects. (6) Evaluation complexity — many valid paths. (7) Safety boundaries — must never exceed permissions.

Q14: How would you test a multi-agent collaborative system?

Answer: Layers: (1) Individual: Test each agent's core capability. (2) Communication: Message format and interpretation. (3) Coordination: Task delegation, dependency ordering. (4) Conflict resolution: When agents disagree. (5) Emergent behavior: Chaos testing. (6) Consensus: Voting/agreement mechanisms. (7) End-to-end: Correct final output.

Q15: Describe your approach to testing tool-use capabilities.

Answer: Layered: L1 - Unit: Tools work with valid inputs, handle errors. L2 - Selection: Right tool picked (labeled dataset). L3 - Parameters: Correct extraction from natural language. L4 - Recovery: Handles timeouts, rate limits. L5 - Security: Resists indirect injection via tool outputs. L6 - Efficiency: Minimum tool calls, parallelizes when possible.

Q16: How do you test for infinite loops and runaway costs?

Answer: Safeguards: (1) Max step limits. (2) Token budgets with abort thresholds. (3) Loop detection (repeated identical actions). (4) Timeout enforcement. (5) Real-time cost tracking. Test by creating scenarios that induce loops (circular deps, impossible tasks) and verify graceful termination.

Q17: What is the ReAct pattern and how do you test it?

Answer: ReAct interleaves: Think → Act → Observe → Think → Act. Test: (1) Thought quality — logical and relevant. (2) Action alignment — follows from reasoning. (3) Observation usage — incorporates results. (4) Convergence — loop converges toward completion. (5) Error handling — adjusts plan on failure. Validate by capturing full traces.

Q18: How do you handle non-determinism in AI testing?

Answer: (1) Statistical testing: Run N times, pass if success > threshold. (2) Temperature=0: Reduce randomness. (3) Semantic assertions: Check meaning, not exact text. (4) Property-based: Properties that must always hold. (5) Fuzzy matching: Cosine similarity > 0.85. (6) Behavioral contracts: Invariants regardless of specific output.

🎯 Scenario-Based & Expert Questions

Q19: Design a test strategy for a customer support AI agent that handles refunds.

Answer: Happy paths: Lookup order, process refund within policy. Edge cases: Expired window, partial refunds, cancelled orders. Authorization: Agent refunds only within limits, escalates higher amounts. Safety: Cannot refund to different accounts, reveals only customer's data. Escalation: Identifies when to hand off (angry customers, legal). Context: Multi-turn conversations, remembers earlier details. Load: 100 concurrent conversations. Monitoring: Refund accuracy, false escalation rate, CSAT.

Q20: How do you test for bias in a hiring AI system?

Answer: (1) Demographic parity: Similar selection rates across groups. (2) Counterfactual: Change only protected attributes, verify scores unchanged. (3) Disparate impact: 4/5ths rule. (4) Proxy detection: Features correlating with protected attributes. (5) Historical bias: Training data may embed discrimination. (6) Intersectional: Test combinations. Tools: AIF360, Fairlearn. Compliance: EEOC, EU AI Act.

Q21: What is "evaluation-driven development" for AI?

Answer: EDD applies TDD to AI: (1) Write evals first — define "good" with test cases. (2) Baseline measurement on current system. (3) Iterate — make changes, compare to baseline. (4) Gate deployments — changes deploy only if evals pass. Benefits: Prevents guesswork, objective progress, enables team collaboration. Use promptfoo or DeepEval in CI/CD.

Q22: How do you test for regulatory compliance (GDPR, EU AI Act)?

Answer: GDPR: Right to erasure, data minimization, no PII in outputs, consent verification. EU AI Act: Risk classification, transparency (users know it's AI), human oversight, documentation, fairness testing. Testing: PII scanning, audit trails, consent flows, documentation checks, third-party audits.

Q23: What are guardrails and how do you test them?

Answer: Safety mechanisms constraining AI: Input: Filter malicious inputs. Output: Scan for PII, toxicity before serving. Behavioral: Prevent dangerous actions. Testing: (1) Red-team with adversarial inputs. (2) Verify legitimate inputs NOT blocked (false positive rate). (3) Test bypass attempts. (4) Measure latency overhead. (5) Test graceful fallback. Tools: Guardrails AI, NeMo Guardrails.

Q24: How do you test AI in regulated industries (healthcare, finance)?

Answer: Added layers: (1) Higher accuracy thresholds (99%+). (2) Explainability (SHAP, LIME). (3) Audit trails for every decision. (4) Human oversight — critical decisions need confirmation. (5) Certified fairness testing. (6) Adversarial robustness. (7) Complete versioning lineage. (8) Validation studies. (9) Third-party audits. (10) Incident response process.

Q25: What is "metamorphic testing" for AI?

Answer: Defines relationships between inputs/outputs rather than exact values — perfect for AI where outputs are unknown. Relations: (1) Permutation shouldn't change classification. (2) Scaling shouldn't change ranking. (3) Negation should flip sentiment. (4) Irrelevant info shouldn't change answer. (5) Consistency — "A > B" and "B > A" can't both hold. Solves oracle problem by testing relationships.

Q26: What tools would you use to build an AI testing pipeline from scratch?

Answer: Unit: pytest + DeepEval. Prompt: promptfoo. RAG: RAGAS. Safety: Giskard + custom red-team. Data: Great Expectations/Pandera. Monitoring: LangSmith/Arize + Evidently. Load: Locust/k6. CI/CD: GitHub Actions. Observability: OpenTelemetry + Grafana. Start simple (promptfoo + pytest), add layers as system matures.

Q27: What is the difference between evaluation and testing for LLMs?

Answer: Evaluation: Measuring capabilities with benchmarks. Answers "how good is this model?" Used during development. Testing: Verifying specific requirements are met. Answers "does this meet our requirements?" Used in CI/CD with pass/fail gates. Evaluation informs decisions; testing enforces standards. Both needed.

Q28: How do you ensure reproducibility in AI testing?

Answer: (1) Fix random seeds (temperature=0). (2) Pin model/API/library versions. (3) Version control test data (DVC). (4) Docker for consistent environments. (5) Fixed test case order. (6) Statistical tests — confidence intervals. (7) Trace logging for debugging. Accept some non-determinism is inherent — design tests robust to it.

Q29: 90-day plan to set up AI testing at a company?

Answer: Days 1-30: Audit systems, create initial eval dataset (100+ cases), set up basic framework, implement critical guardrails, basic monitoring. Days 31-60: CI/CD integration, expand to 500+ cases, drift detection, prompt regression testing, safety scanning. Days 61-90: Full dashboard, automated canary, red-team program, performance benchmarks, documentation, team training. Start with highest-risk areas.

Q30: What metrics would you track on an AI agent production dashboard?

Answer: Quality: Task success rate, hallucination rate, CSAT. Performance: Latency (TTFT, total), throughput, error rate. Cost: Tokens/request, cost/task, daily spend. Safety: Guardrail triggers, toxicity flags, PII events. Agent: Steps/task, tool success rate, loop detection, escalation rate. Business: Tasks automated, time saved. Alert thresholds for each.

• For agentic AI — emphasize safety boundaries, cost controls, and human-in-the-loop
